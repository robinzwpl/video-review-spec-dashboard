# 如何为新版式标定配置

拿到一个新视频、还没有 preset 时，先跑：

```bash
"C:/Program Files/Python314/python.exe" scripts/05_discover.py \
    --input output/frames_ocr.json --output output/layout_report.md
```

想连 preset 草稿一起出：

```bash
"C:/Program Files/Python314/python.exe" scripts/05_discover.py \
    --input output/frames_ocr.json --output output/layout_report.md \
    --emit-preset config/presets/<品类>.yaml --width 1920 --height 1080
```

报告有三节加一张建议阈值表，按下面的顺序判读。

---

## 前提：新视频要跑两遍 OCR

第一遍还没有 preset，`04_ocr.py` **不要给 `--preset`**，它只识别 `default.yaml`
里的通用区（`card_main`、`subtitle`）。这一遍的产物就用来探查版式。

照报告填完 preset 之后，**再跑一遍 04 并带上 `--preset`**，这时才会有底部栏等
品类专属区域的标注。只跑一遍的话，底部栏字段会全部缺失，而且不会报错。

---

## 第一节：候选字段标签

表里列出「跨帧重复出现的短文本」，这些通常就是画面上的字段标签。

**判读**：

- 「文本」列直接抄进 preset 的 `fields.aliases`
- 「平均 y」告诉你这个字段在画面的哪一行，用来判断标签与值的相对位置
- 「出现帧数」越多越可信；只出现 3-4 次的可能是某台机器的特殊内容而不是通用字段

**注意**：值文本也可能混进来（如 "Mini LED"、"四核A73"、"4K 144Hz"）。
区分方法是看「平均 x」—— 同一行里标签在左、值在右，标签的 x 明显偏小且各行对齐。
上例中「屏幕 / 原生刷新 / 色域 / 背光分区 / 亮度范围」的 x 都在 974-1001 附近，
是整齐的左列，即标签；而 "Mini LED" x=898、"四核A73" x=1262 是散的，即值。

---

## 第二节：纵向分布

把文本框按 y 每 50 像素分桶计数。

**判读**：

- 顶部**连续**密集带 = 标题行（品牌 + 型号）。取该带的**下沿**作为 `card.title_max_y`
- 中部密集带 = 参数卡主体
- 画面靠下若有独立密集带 = 底部横排栏，其起始 y 就是 `footer_regions` 的依据

「连续」二字不能省。报告末尾的**建议阈值**表已经按下面这套判读算好了：

| 配置项 | 算法 |
|---|---|
| `card.title_max_y` | 自上而下，只要区间框数不低于全局峰值 35% 就继续归入标题带，遇第一个稀疏区间即止，取该带下沿 |
| 底部栏起始 y | 自底向上，只要不低于最底部区间框数的 40% 就仍在底栏内，第一个明显稀疏的区间就是密度谷，取其起点（保守值） |

以 75 寸电视那次为例：算出的 `title_max_y` 是 150（与人工标定一致），
底部栏起始 y 算出 900（人工实测 912，差 12px，够用作起点）。
注意只看「第一个」密集带会得出 100，把标题下方的副标题行切走。

**别按「空区间」找底部栏边界**——画面中部的文字几乎是连续的，按空档找会一路
走到画面顶部，永远检测不到底栏。必须按密度谷找。

---

## 第三节：region 分布

OCR 阶段会把画面切成若干区域并给每个文本框打上 region 标签。
这一节告诉你每个 region 实际覆盖了多少框、平均位置在哪。

**判读**：如果某个 region 的框数为 0 或极少，说明切分边界不对，需要去调
`ocr.regions` 里那个区域的 box（`default.yaml` 放通用区，品类专属区放 preset），
而不是在这一步硬凑。

**区域名是两层配置之间的接口**：04 按 `ocr.regions` 的 box 裁切并打上 region 名，
06 再按 `footer_regions` 的键名去找抽取器。两边名字对不上**不会报错，只会静默
丢字段**。加载配置时会校验这个契约（键名写错直接抛错，值区没配抽取器会警告），
但坐标填错照样静默——所以标定完一定要看这一节的框数。

---

## 常见误判

| 误判 | 后果 | 怎么避免 |
|---|---|---|
| 把值当成标签 | 字段表里混进一堆数值，解析结果全是 None | 看平均 x 是否成列对齐 |
| 把字幕当成标签 | 字幕区域的高频词污染字段表 | 字幕通常在画面最底部且 x 居中，与参数卡不同列 |
| 开篇总览页的高频词 | 混入"32款""一起拆开看"这类噪声 | 先设 `exclude_before_sec` 再跑 discover |
| 用等分切底部栏 | 字段覆盖率极低（实测 2/32） | 必须按实测 x 边界切，见 troubleshooting 第 11 条 |
| 只跑一遍 OCR 就填底部栏 | 底部栏字段全缺且不报错 | 填完 preset 后必须重跑 04 并带 `--preset` |
| 把草稿的 `type: text` 直接用 | 数值字段全落进兜底文本，图表取不到数 | 草稿里带 `# TODO` 的 type 必须逐个照 field-cookbook 改 |

---

## 标定完之后的验证

填好 preset 后跑解析，然后核对两件事：

1. 机型数是否符合预期（视频里展示了多少款）
2. 字段覆盖率 —— 跑 `08_specs_table.py` 会打印每个字段的覆盖统计，
   某个字段覆盖率异常低，多半是标签没配对或区域切错了
3. 数值的数量级 —— OCR 丢连字符很常见（「100-200级」→「100200级」→ 解析成 10020）。
   扫一眼最大值，异常就回看 `raw` 原文与原始帧
