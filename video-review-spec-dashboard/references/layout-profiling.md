# 如何为新版式标定配置

拿到一个新视频、还没有 preset 时，先跑：

```bash
"C:/Program Files/Python314/python.exe" scripts/05_discover.py \
    --input output/frames_ocr.json --output output/layout_report.md
```

报告有三节，按下面的顺序判读。

---

## 第一节：候选字段标签

表里列出「跨帧重复出现的短文本」，这些通常就是画面上的字段标签。

**判读**：

- 「文本」列直接抄进 preset 的 `fields.aliases`
- 「平均 y」告诉你这个字段在画面的哪一行，用来判断标签与值的相对位置
- 「出现帧数」越多越可信；只出现 3-4 次的可能是某台机器的特殊内容而不是通用字段

**注意**：值文本也可能混进来（如 "Mini LED"、"四核A73"、"4K 144Hz"）。
区分方法是看「平均 x」—— 同一行里标签在左、值在右，标签的 x 明显偏小且各行对齐。
上例中「屏幕 / 原生刷新 / 色域 / 背光分区 / 亮度范围」的 x 都在 974-1001 附近，
是整齐的左列，即标签；而 "Mini LED" x=898、"四核A73" x=1262 是散的，即值。

---

## 第二节：纵向分布

把文本框按 y 每 50 像素分桶计数。

**判读**：

- 顶部第一个密集带 = 标题行（品牌 + 型号）。取该带的上界作为 `card.title_max_y`
- 中部密集带 = 参数卡主体
- 画面靠下若有独立密集带 = 底部横排栏，其起始 y 就是 `footer_regions` 的依据

以 75 寸电视那次为例：标题带在 y73-142，参数主体在 y269-814，
底部栏在 y989-1003 —— 三个带分得很清楚。

---

## 第三节：region 分布

OCR 阶段会把画面切成若干区域并给每个文本框打上 region 标签。
这一节告诉你每个 region 实际覆盖了多少框、平均位置在哪。

**判读**：如果某个 region 的框数为 0 或极少，说明切分边界不对，
需要回到 `04_ocr.py` 的区域定义去调，而不是在这一步硬凑。

---

## 常见误判

| 误判 | 后果 | 怎么避免 |
|---|---|---|
| 把值当成标签 | 字段表里混进一堆数值，解析结果全是 None | 看平均 x 是否成列对齐 |
| 把字幕当成标签 | 字幕区域的高频词污染字段表 | 字幕通常在画面最底部且 x 居中，与参数卡不同列 |
| 开篇总览页的高频词 | 混入"32款""一起拆开看"这类噪声 | 先设 `exclude_before_sec` 再跑 discover |
| 用等分切底部栏 | 字段覆盖率极低（实测 2/32） | 必须按实测 x 边界切，见 troubleshooting 第 11 条 |

---

## 标定完之后的验证

填好 preset 后跑解析，然后核对两件事：

1. 机型数是否符合预期（视频里展示了多少款）
2. 字段覆盖率 —— 跑 `08_specs_table.py` 会打印每个字段的覆盖统计，
   某个字段覆盖率异常低，多半是标签没配对或区域切错了
